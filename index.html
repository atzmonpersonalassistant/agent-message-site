(c) Where does "unprocessed rows" come from?

It is computed by bin/should-run.py from message_log against state/last-processed.json, before Codex/classification starts.

Relevant code:
  state_path = root/'state/last-processed.json'
  last_row = int(old.get('row_number') or old.get('last_processed_row') or 1)
  rows = sheet_values(env['SHEET_LOG_RANGE'])
  for idx, row in enumerate(rows[1:], start=2):
      if idx <= last_row or len(row) < 3 or not row[2].strip():
          continue
      unprocessed.append(message_from_row(row, idx))
  msg['unprocessed_count'] = len(unprocessed)
  msg['first_unprocessed_row'] = unprocessed[0].get('row_number')
  msg['last_unprocessed_row'] = unprocessed[-1].get('row_number')

There is no separate classifier that can see unprocessed rows and decide not to act. If should-run.py successfully sees rows greater than last_row, it writes current-input.json and exits 0, then Codex is invoked. During the gap it was not seeing the rows because the gog Sheets call failed before rows were returned.
